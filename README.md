# Grey Knight — 灰骑士

北京理工大学大二web开发小学期作业

> 一款基于原生 HTML5 / CSS3 / JavaScript ES Modules 的卡牌对战 RPG 游戏。
> 故事驱动的分支叙事 × 回合制卡牌战斗 × 图鉴收集。

---

## 项目简介

《Grey Knight》以中世纪奇幻为背景，玩家扮演骑士 **阿尔德里克**，在剿匪平叛的过程中逐渐揭开权力背后的阴谋。游戏采用**分支叙事**结构，玩家的选择将决定剧情走向与最终结局。

核心玩法为**回合制卡牌对战**：玩家在 5 列棋盘上部署单位卡牌，与敌方单位对拼，击溃敌方英雄即可获胜。战斗中包含先手、入场效果、溢出伤害等策略要素。

---

## 技术栈

| 层级 | 技术 |
|------|------|
| 页面结构 | HTML5 |
| 样式 | CSS3（自定义主题变量） |
| 逻辑 | 原生 JavaScript ES Modules |
| 数据持久化 | `localStorage`（账号、进度、图鉴、奖励） |
| 构建 | 无打包工具，纯静态部署 |

**不使用 React、Vue 或任何前端框架。**

## 游戏功能

### 账号系统
- 注册 / 登录（`localStorage` 明文存储，仅用于课程演示）
- 多账号切换，进度独立保存

### 分支叙事
游戏第一章结束后，玩家面临关键抉择，决定后续剧情走向：

```
第一章: node-1（东疆剿匪，心生疑云）
    │
    ├── 查账线（audit）
    │   node-2 → node-3 → node-4 → node-6
    │   账簿露秘 → 同袍无踪 → 匪首落定 → 真相大白
    │
    └── 叛徒线（traitor）
        rebel-2 → rebel-3 → rebel-4 → rebel-5
        边境异动 → (待续) → (待续) → (待续)
```

- 重新打第一章可重新选择分支
- 分支切换时进度重置，但图鉴和已获卡牌保留

### 卡牌战斗
- **5 列棋盘**：双方在 5 列上部署单位，同列对拼
- **能量系统**：每回合能量回满，出牌消耗能量
- **入场效果**：抽牌、回能、直伤英雄、治疗英雄
- **先手机制**：拥有 `firstStrike` 关键词的单位优先攻击，独占先手时敌方不反击
- **溢出伤害**：对拼中击杀单位的多余伤害会穿透到英雄
- **跳过战斗**：支持跳过战斗快速推进（调试用）

### 敌方 AI
- 每回合按章节配置召唤单位
- 75% 概率优先堵住玩家有单位的列（阻止直接打脸）

### 战斗结算
- 战后剧情展示
- 奖励卡牌选择（影响后续可用牌组）
- 敌方图鉴批量解锁
- 分支切换与进度保存

### 图鉴系统
- 收集已遭遇的玩家卡牌与敌方卡牌
- 章节结算后统一解锁，不在战斗中实时写入
- 搜索、筛选与规则查阅

### 剧情地图
- 可视化节点路线
- 当前节点高亮，已通过节点绿色，未解锁节点灰色
- 路线由 `MAP_ROUTES` 显式声明，确保分支不串线

## 快速开始

1. 将项目部署到任意静态服务器（如 VS Code Live Server、Nginx、Apache）
2. 浏览器打开 `index.html`
3. 注册账号 → 登录 → 开始游戏

> 注意：项目使用 ES Modules 和绝对路径（`/css/...`、`/game/...`），需通过 HTTP 服务访问，不能直接双击 HTML 文件打开。
